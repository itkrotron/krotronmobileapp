# KROTRON — ไฟล์ประกาศเวอร์ชัน

repo นี้เก็บไฟล์เดียว: **[`version.json`](version.json)** — ไฟล์ที่บอกแอปบนมือถือพนักงานว่า
เวอร์ชันล่าสุดคือตัวไหน

**ตัวไฟล์ `.apk` ไม่ได้อยู่ที่นี่** อยู่บน Google Drive · สองอย่างนี้เก็บคนละที่โดยตั้งใจ

| | เก็บที่ | เพราะ |
|---|---|---|
| `version.json` | **GitHub** | raw URL คงที่ตลอดกาล · แอปฝัง URL นี้ไว้ข้างในและ**แก้จากระยะไกลไม่ได้** ถ้ามันย้ายที่ เครื่องที่ลงไปแล้วทุกเครื่องจะตรวจอัปเดตไม่ได้อีกเลย |
| `Krotron_*.apk` | **Google Drive** | ไฟล์ใหญ่ ไม่เหมาะกับ git · และ File ID คงที่ได้ถ้าใช้ "Manage versions" |

> 🔓 **repo นี้ต้องเป็น Public** — ถ้าเป็น Private แอปต้องมี token ฝังอยู่ ซึ่งใครแกะ APK ก็เอาไปได้
> ไฟล์นี้มีแค่เลขเวอร์ชันกับ changelog ไม่มีอะไรเป็นความลับ

## 📋 ขั้นตอนตอนปล่อยเวอร์ชันใหม่ ทำตามลำดับนี้เท่านั้น

### 1. เอาค่าจริงออกมาจาก APK — ห้ามพิมพ์เอง

```bash
# versionCode และ versionName
aapt dump badging Krotron_1_1_0_XXXXXXXX_XX.apk | head -1

# SHA-256
sha256sum Krotron_1_1_0_XXXXXXXX_XX.apk
# บน Windows PowerShell:  Get-FileHash -Algorithm SHA256 ไฟล์.apk
```

> 🔴 **ข้อที่พลาดแล้วเสียหายที่สุดในทั้งกระบวนการ**
>
> `versionCode` ของโปรเจกต์นี้ **ตัว build สร้างเองจากวันที่** เป็นเลขสิบหลักอย่าง `2026081908`
> ไม่ใช่ตัวนับ 1, 2, 3 และ**ไม่มีบรรทัดใน `build.gradle` ให้แก้**
>
> ถ้าใส่เลขเล็ก ๆ ลงไป (เช่น `6` ตามตัวอย่างที่สเปกมักเขียน) แอปจะเทียบแล้วสรุปว่า
> **ตัวเองใหม่กว่าอยู่แล้ว → ทุกเครื่องจะไม่ได้รับแจ้งอัปเดตอีกเลย** และ
> **ไม่มี error ขึ้นที่ไหนเลย** เพราะระบบถูกออกแบบให้เงียบเมื่อล้มเหลว
>
> → **ก๊อปเลขจากผลลัพธ์ของ `aapt` มาวาง อย่าคิดเลขเอง**

### 2. อัปโหลด APK ขึ้น Google Drive

**ครั้งแรก** อัปโหลดตามปกติ แล้วคลิกขวาที่**ตัวไฟล์** (ไม่ใช่โฟลเดอร์) → Share →
เปลี่ยนเป็น **"Anyone with the link"**

**ครั้งต่อ ๆ ไป** คลิกขวาที่ไฟล์เดิม → **Manage versions → Upload new version**

> ⛔ **ห้ามลบไฟล์เก่าแล้วอัปโหลดใหม่แยก** — File ID จะเปลี่ยน แล้ว `apkUrl` ในไฟล์นี้จะชี้ไปที่ที่ไม่มีอะไรอยู่
> เครื่องที่กดอัปเดตจะโหลดไม่ได้ทุกเครื่อง

### 3. แปลงลิงก์ Drive เป็น direct download

ลิงก์ที่ Drive ให้มาหน้าตาแบบนี้

```
https://drive.google.com/file/d/1AbCdEfGhIjKlMnOpQrStUvWxYz/view?usp=sharing
                                └──────── FILE_ID ────────┘
```

เอา `FILE_ID` มาประกอบใหม่เป็น

```
https://drive.google.com/uc?export=download&id=1AbCdEfGhIjKlMnOpQrStUvWxYz
```

### 4. แก้ `version.json` ใน repo นี้

| field | ต้องแก้ทุกรอบไหม | เอาค่ามาจากไหน |
|---|---|---|
| `versionCode` | ✅ **ทุกรอบ** | ผลลัพธ์ `aapt` ข้อ 1 |
| `versionName` | ✅ ทุกรอบ | ผลลัพธ์ `aapt` ข้อ 1 |
| `sha256` | ✅ **ทุกรอบ** | ผลลัพธ์ `sha256sum` ข้อ 1 |
| `changelog` | ✅ ทุกรอบ | เขียนเองให้พนักงานอ่านรู้เรื่อง |
| `apkUrl` | ❌ ครั้งแรกครั้งเดียว | ข้อ 3 · ถ้าใช้ Manage versions ตามข้อ 2 จะไม่เปลี่ยนอีก |
| `forceUpdate` | ❌ เฉพาะเมื่อจำเป็น | ดูด้านล่าง |

### 5. ตรวจก่อนกด Commit

- [ ] `versionCode` เป็นเลขสิบหลัก ขึ้นต้นด้วยปี เช่น `20260819xx`
- [ ] `versionCode` **มากกว่า**ค่าเดิมที่อยู่ในไฟล์
- [ ] `sha256` มี 64 ตัวอักษร และมาจากไฟล์ตัวที่อัปโหลดขึ้น Drive จริง ๆ
- [ ] `apkUrl` **ไม่ใช่ข้อความตัวอย่าง** — ต้องเป็นลิงก์จริง ไม่ใช่ `PASTE_..._HERE`
- [ ] เปิด `apkUrl` ในหน้าต่างไม่ระบุตัวตน (incognito) แล้วไฟล์ต้องโหลดได้ **โดยไม่ต้องล็อกอิน**

## ⏱️ หลัง commit แล้ว **รออีก ~5 นาที** ก่อนคาดหวังว่าเครื่องจะเห็น

`raw.githubusercontent.com` เสิร์ฟผ่าน CDN ที่แคชไฟล์ไว้ · หลังกด commit ไฟล์บน GitHub
เปลี่ยนทันที แต่ **CDN ยังส่งของเก่ากลับมาได้อีกราว 5 นาที** และ**ใส่ query string ต่อท้าย
เพื่อล้างแคชไม่ได้ผล** — raw ตัดทิ้ง

**ทำไมสั่งข้ามไม่ได้:** แอปใส่ `Cache-Control: no-cache` ไปในคำขอแล้ว แต่หัวข้อนั้น
**สั่งได้แค่แคชในตัวเครื่องเอง สั่งเซิร์ฟเวอร์แคชของ GitHub ไม่ได้** · GitHub ติดป้าย
`Cache-Control: max-age=300` มากับไฟล์ แปลว่ามันจะเสิร์ฟของเดิมจนครบ 5 นาที ไม่ว่าใครจะขออะไร

**และ 5 นาทีเป็นเพดาน ไม่ใช่จังหวะที่ทุกเครื่องเห็นพร้อมกัน** — GitHub มีเซิร์ฟเวอร์แคชหลายตัว
แต่ละตัวหมดอายุคนละเวลา ยิงติดกัน 3 ครั้งอาจได้คนละตัว:
```
X-Served-By: cache-bkk2280038-BKK   Source-Age: 0
X-Served-By: cache-bkk2280030-BKK   Source-Age: 8
X-Served-By: cache-bkk2280029-BKK   Source-Age: 16
```
→ **เครื่องหนึ่งเห็นไฟล์ใหม่แล้ว อีกเครื่องยังไม่เห็น เป็นเรื่องปกติ** อย่าสรุปจากเครื่องเดียว

**เคล็ดตอนทดสอบ:** เขียน changelog ให้ต่างจากรอบก่อนชัด ๆ · กล่องที่เด้งบนเครื่องจะบอกเอง
ว่ากำลังอ่านไฟล์รอบไหนอยู่ — ไม่ต้องเดาว่าเป็นแคชหรือเป็นบั๊ก

> ⚠️ **อาการนี้หลอกมาก:** กดทดสอบทันทีแล้วเครื่องขึ้น "ใช้เวอร์ชันล่าสุดอยู่แล้ว"
> ดูเหมือนระบบพัง ทั้งที่ทุกอย่างถูกหมด แค่ยังไม่ถึงเวลา
>
> **วิธีเช็คว่าไฟล์จริงขึ้นหรือยัง โดยไม่ผ่าน CDN** — ดูที่หน้า repo บนเว็บ GitHub
> (หน้าเว็บอ่านจากตัวจริง ไม่ผ่าน CDN ตัวเดียวกับ raw) ถ้าหน้าเว็บถูกแล้ว = commit สำเร็จ
> ที่เหลือแค่รอ

## 🚨 `forceUpdate`

`false` = พนักงานกด "ไว้ทีหลัง" ได้ · **ใช้ค่านี้เป็นปกติ**

`true` = บังคับอัปเดตก่อนใช้งานต่อ · ใช้เฉพาะเวอร์ชันที่ถ้าไม่อัปเดตแล้วจะทำงานผิด เช่น
แก้บั๊กที่ทำให้ข้อมูลผิด หรือเปลี่ยนวิธีคุยกับเซิร์ฟเวอร์

> ⚠️ **ก่อนตั้งเป็น `true` ให้นึกถึงพนักงานที่อยู่ต่างจังหวัดสัญญาณไม่ดี** — เขาจะใช้แอปไม่ได้เลย
> จนกว่าจะโหลดไฟล์เสร็จ · ใบงานที่ปิดแล้วแต่ยังไม่ได้ส่งยังอยู่ในเครื่อง การติดตั้งทับไม่ทำให้หาย
> แต่เขาจะทำงานต่อไม่ได้จนกว่าจะโหลดจบ
